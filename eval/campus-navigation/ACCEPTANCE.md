# 校园整程验收冻结规则

**整程成功率是唯一研究续派指标。** 新候选与当前冻结基线在同版全部整程试次配对比较。只在整程提升超过评测噪声时派下一轮训练或扩量。短段成功率、SPL、楼梯单项和离线指标用于定位问题。

## 第一次对跑前冻结

- 以 [封存清单](heldout-v1.manifest.json) 的 81 回合为现有套件入口。验收方先按该版本校验完整性，确认全部回合是从 A 到 B 的完整试次。冻结只读的验收登记应包含路线 ID 和起终点、密度档和行人脚本、地形/楼梯、种子、分组及分母、场景和传感器配置、定位和初始化、评测器与依赖版本，以及脚本、地图、资产和清单的 SHA-256。封存轨迹与参考路径仅供验收方读取。
- 固定候选与基线的权重、配置和版本后再开跑。首轮经典对照采用 Nav2 全栈，拿到同版有效成绩后作为可比基线。开发集用于联调和候选选择，留出验收由独立评测方统一运行。发布汇总、可复核的逐回合终止事件及哈希。
- 按 [评测协议](EVAL_PROTOCOL.md) 从 A 自主到 B。起点容差 10 cm，目标半径 2 m，预算为 90 s + 最短路长度 / 0.5 m/s。终止优先级为失败、成功、超时。跌倒、禁区侵入、安全员停止、卡死或需接管复位的碰撞计失败。跨层目标还须在目标楼层，冻结清单中须通过的楼梯须完成。评测方在开跑前核对实现与上述口径一致。
- 地图、出生点、门洞、行人行为、步长、评测规则或试次集一旦改变，登记为新版并冻结后重跑基线和候选。旧版结果保留。基础设施中断记录在相应 ops 文件，按锁定配置重跑受影响的整组配对并保留原始日志。任一试次未得到有效结果时整批标记待复核。每个有效超时、碰撞失败、跌倒或算法中断都保留在分母。

## 判定与续派

成功率 = 成功回合数 / 全部冻结试次数。报告双方成功数/总数、百分点差值和按路线聚类的配对 95% 区间，同一路线的密度与种子一起重采样；开跑前登记统计脚本及种子。保留由失败变成功和由成功变失败的配对明细。

- 差值为正且区间下界大于零，才进入下一轮训练或扩量评审。
- 持平、下降或改善未超过噪声，立即停该方向的扩训和同方向研究续派，由人工复核任务拆分、失败归因和接口。复核记录写明证据、拟改层与新方向的外部复现工单。任一方缺有效整程结果也先挂起续派。
- 15–44 m 短窗、100–180 m 长段、单项指标或个别成功演示可以用于诊断。完整路线各密度、距离桶和楼梯子集同时报数，派单用冻结整程总成功率。
